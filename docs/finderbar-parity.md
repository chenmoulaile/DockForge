# Finder 栏逐区对标审计（T-300）

- 审计日期：2026-10-25
- 审计基准：MyDockFinder 的 MyFinder 栏用户可感知功能（官方 README、Steam 描述、社区截图；不逆向实现）
- 账本事实：审计时 Finder Bar 模块**尚未开工**（M2/T-017 起全部 TODO；仓库 `src/` 下无 finderbar 实现，`grep -r "finderbar" src/` 零命中——P5 提示词假设"P0 Finder Bar 基础已完成"，与账本不符，以账本为准）。因此本矩阵几乎所有条目为"缺失"，每一项都映射到 M2 既有队列或 P5 新增任务。
- 编号映射：本审计引用 C-31..C-34、ADR-0037..0041（P5 提示词的 C-18..C-21、ADR-0024..0028 顺延）。

## 明确不做

| 功能 | 理由 |
|---|---|
| 完整菜单栏接管（隐藏目标窗口自身菜单栏） | ADR-0037：需 hook 目标进程，风险不可救 |
| 托盘图标原位接管（移走系统托盘） | ADR-0038：需要 hook explorer；镜像方案已满足感知需求 |
| 伪造托盘图标数据 | ADR-0038 禁止项 |

## 结论

- Finder 栏 24 项功能：**已对齐 0 / 缺失 21 / 明确不做 3**。骨架级前置是 M2 的 Finder Bar 本体（T-017 起），其余按 T-301（左）→ T-302（中）→ T-303/304/305/306/307（右）顺序推进。
- 可复用的既有资产：RunningTracker 的前台窗口轮询（T-012）、DWM 缩略图管线（T-015）、材质降级链（ADR-0008）、设置窗口的防抖保存/发布模式（T-050）、硬件控制底座（T-068 完成后）。
- 执行顺序不变：T-051（热重载）→ P1.5 → P2 → P4 修复 → P5 Finder 栏任务。P4/P5 的修复与实现都依赖这些前置，插入只会打乱依赖链。
