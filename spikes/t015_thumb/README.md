# T-015 spike — DwmRegisterThumbnail

结论全部来自本机实测（单显示器 2880x1920 @192 DPI，工作区 0,0,2880,1824，
Windows build 26300）。原始输出在 `evidence/T-015/tmp_*.txt`。

## 1. 可用性

`DwmRegisterThumbnail` + `DwmQueryThumbnailSourceSize` + `DwmUpdateThumbnailProperties`
全链路 `hr=0x0`。源尺寸查询返回真实窗口尺寸（如 `260x160`）。

- 冷注册 219–609ms（含 DWM 首帧合成），暖注册 0ms。**必须预热**，不能算进交互预算。
- `WS_EX_NOREDIRECTIONBITMAP` 目标窗与普通目标窗逐项结果相同 → Dock 的 DComp 窗口
  可以直接承载缩略图。
- 句柄无泄漏：40 次 register/unregister 配对后 `gui_objects 8 -> 8`、`user_objects 19 -> 19`。
- 目标窗用 GDI 画背景（`RGB(8,9,11)`）时缩略图**绘制在背景之上**，符合预期。

## 2. 渲染数量存在经验上限（未定因，按数据用）

同一目标窗注册 N 个缩略图后，沿整窗做颜色 bbox 扫描统计"实际渲染了几个"：

| 槽宽×高 (DIP) | N | 目标窗宽 (px) | 渲染成功 |
|---|---|---|---|
| 110x70 | 8 | 1928 | **8** |
| 120x90 | 8 | 2144 | **8** |
| 130x70 | 8 | 2304 | **8** |
| 130x130 | 8 | 2304 | **8** |
| 140x90 | 6 | 1856 | **6** |
| 140x70 | 8 | 2496 | **8** |
| 150x70 | 8 | 2656 | 7 |
| 160x70 | 8 | 2752 | 7 |
| 170x70 | 8 | 2848 | 7 |
| 180x70 | 8 | 2944 | 6 |
| 200x130 | 4 | 2152 | 3 |
| 200x130 | 5 | 2576 | 4 |
| 200x130 | 6 | 2576 | 4 |
| 200x130 | 8 | 3424 | 6 |

**已排除的假设**（每条都单独跑过，结果不变）：注册节奏（`--pump-ms=120`）、
重注册、目标窗脏区、源重绘、`WS_EX_TOPMOST`、布局方向（`--vertical=1`）、
注册顺序（`--reverse=1` 时缺的仍是最高的那个索引，不是最后注册的）、槽高
（40/65/100/130 同结果）。

**未定因**：渲染数随槽宽单调下降，但不是"总像素预算"（200x130 的 4 个 = 416k px²，
110x70 的 8 个 = 246k px²；而 200x130 的 6 个 = 624k px² 也渲染了 6 个）。
也不完全由窗口宽度决定（`--pad=100` 加宽 200 DIP 后反而从 4 变 5；`--pad=600`
让窗口超出屏幕右边缘后变 0 —— 这部分是"超出屏幕不合成"，属正常）。

**工程结论**：不猜规则，按实测安全区设计。Dock 预览弹窗取 **110x70 DIP/槽、gap 8 DIP、
最多 8 槽**（192 DPI 下 220x140 px/槽，弹窗 964x98 DIP = 1928x196 px），
重复跑 3 次全部 8/8 稳定。契约里写死这个上限并留验证脚本。

## 3. 最小化不黑屏

`--minimize=2`：`ShowWindow(SW_MINIMIZE)` 后泵 700ms 再采样，缩略图仍是源窗口最后一帧
（`got=(134,202,154)` 与最小化前一致，`best_delta=0`）。**DWM 保留末帧，不需要自己缓存。**
但这条只覆盖"源进程仍在"的情形；进程退出后缩略图会变空白，需要应用层决定是否移除槽位。

## 4. 测量工具本身是主要风险（三次重写）

1. **DIP/物理像素混用**：把 DIP 当物理像素传给 `rcDestination`，192 DPI 下采样点
   y=1840 超出工作区 1824，采到桌面，全部误判 `NO_THUMBNAIL`。修法：所有几何走
   `Px(dip) = dip * scale`，`scale = lround(GetDpiForSystem()/96.0)`。
2. **单点采样无法区分"没画"与"画在别处"**：改为每槽 7 点 + `best_delta`/`at_x`，
   再加整行 `ScanRow`（把每种源颜色匹配成 `run source=N x=.. width=..`）与整窗
   `ScanBox`（`box source=N x=.. y=.. size=WxH hits=..` 或 `ABSENT`）。
3. **`GetPixel(屏幕DC)` 每像素约 1ms**，2576px 一行要 77s，每次都撞超时。改为
   `CreateDIBSection` + 一次 `BitBlt`（`biHeight = -h` top-down，BGRA 顺序
   `px[2],px[1],px[0]`）。**DIB 必须读完行之后再 `DeleteObject`**，否则 `bits` 悬空。

## 5. 对主工程的强制约束

- 预览弹窗必须是独立窗口（Dock 窗口的 region 会裁掉弹窗、且高度固定）。
- 弹窗用普通窗口（不加 `WS_EX_NOREDIRECTIONBITMAP`）+ GDI/D2D-HWND 画底，缩略图由
  DWM 合成在其上 —— 这条路径已实测，不要为了材质把它改成 DComp 再赌 z 序。
- 悬停 ≥400ms 触发；≤8 槽；槽 110x70 DIP、gap 8 DIP。
- 注册成本 219–609ms 必须在悬停延迟里吸收（异步或预热），不能阻塞 UI 线程。
- 注销必须配对，`DwmUnregisterThumbnail` 在窗口销毁前调用。
